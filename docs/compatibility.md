# 兼容性与验证

适配目标是已登录的迅雷 Docker 本地下载服务，当前协议依据迅雷引擎 **3.21.0**。请以 `/launcher/status` 的 `running_version` 为准，Docker 包装器的镜像标签不一定与引擎版本相同。

## 范围

首版覆盖本地下载任务的投递、查询与控制，不包含迅雷账号登录全流程、会员购买、云盘文件管理、媒体播放或插件管理。没有使用旧版认证流程中依赖的 JavaScript 执行器。

当前接口并非迅雷正式公开的稳定 API；上游网页协议变化可能需要更新适配器。虽然较新版本可能继续使用相同协议，不能由版本号直接推断兼容。公开发布不包含真实设备地址、账号、令牌、下载记录或私有测试数据。

## 自动化验证

CI 使用模拟上游测试认证、请求编码、任务状态、文件索引、错误处理、幂等与操作持久化；发布前执行完整测试和 race detector，并对最终容器做非 root、只读根文件系统的启动与健康检查。

2026-09-11 的 [CI 验证](https://github.com/myth815/xunlei-api/actions/runs/34586420062) 已全部通过：格式、vet、race tests、工作流校验、Linux amd64 / arm64 交叉编译、容器构建和健康检查。该次 amd64 测试镜像展开大小为 **8,568,127 字节，约 8.17 MiB**；这是本地镜像大小，不是 GHCR 下载时的压缩传输大小。

模拟测试用于检查 API 自身逻辑，无法替代真实迅雷的行为验证。下面分别记录真实验证结果与尚未完成的场景。

## 真实环境验证记录

测试日期：**2026-09-11**。测试对象为已登录的迅雷引擎 **3.21.0**，通过本项目 API 执行请求。写操作使用专用目录、自建下载数据和测试种子，删除测试仅操作这些测试文件。

仓库的 `TestLiveTaskLifecycle` 和 `TestLiveDeleteFiles` 两项真实环境测试均通过，合计约 **45.6 秒**。测试运行时 API 未挂载下载目录，磁盘文件的保留、删除与内容摘要另行在 NAS 上独立检查。普通 CI 未配置真实迅雷地址，因此不会对真实下载设备执行这些写操作。

| 项目 | 验证状态 |
| --- | --- |
| 单密钥认证 | 正确 Bearer Key 可以访问；缺失或错误 Key 被拒绝；仅在 URL 中提供 Key 不能通过认证 |
| 浏览器来源检查 | 未允许的来源返回 403；配置的 Chrome 扩展来源预检返回 204 |
| 设备、目录与任务查询 | 设备在线、已登录；目录查询和创建成功；任务列表和按 ID 查询成功 |
| 用户目录路径转换 | 根目录返回 `display_path`；已在真实设备上使用 `/迅雷下载` 路径完成逐级解析与子目录查询 |
| HTTP / HTTPS 解析、投递与完成 | 自建 4 MiB HTTP 测试文件及公开 HTTPS README 均成功创建任务并完成下载；4 MiB 文件经历暂停和恢复后，SHA-256 与源文件一致 |
| 幂等投递 | 相同请求与相同 `Idempotency-Key` 返回同一个 operation，没有创建重复任务 |
| 暂停与恢复 | 暂停后回读 `paused`，恢复后回读 `running` |
| 只删除任务记录、保留文件 | 删除后查询任务返回 404；在 NAS 上独立检查确认测试文件仍然存在 |
| 同时删除记录与文件 | `delete_files=true` 后查询任务返回 404；在 NAS 上独立检查确认测试文件已删除 |
| 原始种子上传与解析 | 两文件 `.torrent` 上传和解析成功；已适配真实响应省略零索引的行为 |
| BT 部分文件投递 | 选择 `[1]` 创建任务成功，回读 `sub_file_index=1`，暂停成功；没有可用 peer，未验证完整下载及最终落盘内容 |
| 失败重试 | 模拟上游测试通过；真实环境专用 404 链接仍被迅雷保持为 `running`，尚未进入可执行 retry 的失败状态 |

文件保留和删除的检查由测试过程在 NAS 上独立完成。API 本身没有下载磁盘访问权，因此没有将这一测试能力变成运行时保证：连文件删除后仍报告 `files_deleted=null`，在无法确认完整结果时进入 `unknown_outcome`。同一引擎版本的一次成功验证也不能保证其他部署中的文件系统行为。

迅雷网页协议有时省略 BT 文件的 `file_index=0`。适配器仅在文件树完整、只有一个叶子缺少索引、其余索引恰好覆盖 `1..n-1` 时将该叶子规范化为索引 `0`；其他不完整或歧义情况仍拒绝部分文件选择。此规则已经使用真实两文件种子响应和自动化测试验证。

## 已知边界

- 控制请求返回成功后，迅雷可能先排队或异步处理；以 operation 和后续任务状态为准。
- 任务进度达到 100% 可能仍在校验；完成以任务 phase 为准。
- API 不直接读取下载磁盘，因此不能独立验证文件删除。
- 上游任务创建没有原生幂等保证，不能承诺所有崩溃窗口内严格只创建一次；结果未知时必须核查。
- 重试会生成新的任务 ID；保留旧任务信息不代表迅雷仍保留旧任务记录。
- 原始种子上传存在并不代表全部私有 tracker、BT v2 / hybrid 种子都兼容。
- BT 选择已验证投递参数与任务控制，尚未验证由 peer 传输完成后的最终文件集合。
- 单实例、单迅雷设备、单数据目录。批量控制、完成通知、多设备管理和 Kubespider 入站接口兼容不在首版范围。
