# 兼容性与验证

适配目标是已登录的迅雷 Docker 本地下载服务，当前协议依据迅雷引擎 **3.21.0**。请以 `/launcher/status` 的 `running_version` 为准，Docker 包装器的镜像标签不一定与引擎版本相同。

## 范围

首版覆盖本地下载任务的投递、查询与控制，不包含迅雷账号登录全流程、会员购买、云盘文件管理、媒体播放或插件管理。没有使用旧版认证流程中依赖的 JavaScript 执行器。

当前接口并非迅雷正式公开的稳定 API；上游网页协议变化可能需要更新适配器。虽然较新版本可能继续使用相同协议，不能由版本号直接推断兼容。公开发布不包含真实设备地址、账号、令牌、下载记录或私有测试数据。

## 自动化验证

CI 使用模拟上游测试认证、请求编码、任务状态、文件索引、错误处理、幂等与操作持久化；发布前执行完整测试和 race detector，并对最终容器做非 root、只读根文件系统的启动与健康检查。

模拟测试用于检查 API 自身逻辑，无法替代真实迅雷的行为验证。具体已执行的真实环境测试结果在发布前补充于此；未实测的能力不能视为已经完成端到端验证。

## 已知边界

- 控制请求返回成功后，迅雷可能先排队或异步处理；以 operation 和后续任务状态为准。
- 任务进度达到 100% 可能仍在校验；完成以任务 phase 为准。
- API 不直接读取下载磁盘，因此不能独立验证文件删除。
- 上游任务创建没有原生幂等保证，不能承诺所有崩溃窗口内严格只创建一次；结果未知时必须核查。
- 重试会生成新的任务 ID；保留旧任务信息不代表迅雷仍保留旧任务记录。
- 原始种子上传存在并不代表全部私有 tracker、BT v2 / hybrid 种子都兼容。
- 单实例、单迅雷设备、单数据目录。批量控制、完成通知、多设备管理和 Kubespider 入站接口兼容不在首版范围。
